## 三、数据库初始化

### 3.1 导入菜单 SQL（首次使用）

```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -f /tmp/hospital_menu.sql"
```

> ⚠️ **注意**：必须使用 **完整路径** 调用 gsql，因为默认不在 PATH 中。`/usr/local/opengauss/bin/gsql` 是 gsql 的正确位置。

### 3.2 导入测试数据（可选）

```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -f /tmp/test_data.sql"
```

> ⚠️ **注意**：导入测试数据前，如果数据库序列不同步，会导致 `duplicate key` 错误。详见"常见错误"章节。

### 3.3 修复序列同步问题（如果出现 duplicate key）

```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -c \"SELECT setval('hospital_ward_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_ward)); SELECT setval('hospital_bed_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_bed)); SELECT setval('hospital_visit_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_visit)); SELECT setval('hospital_prescription_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_prescription)); SELECT setval('hospital_prescription_item_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_prescription_item)); SELECT setval('hospital_bill_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_bill)); SELECT setval('hospital_department_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_department)); SELECT setval('hospital_doctor_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_doctor)); SELECT setval('hospital_patient_seq', (SELECT COALESCE(MAX(id), 0) + 1 FROM hospital_patient));\""
```

或直接运行项目根目录下的 `fix_seqs.sql`：

```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -f /tmp/fix_seqs.sql"
```

响应中的 `data` 字段即为 token。

## 五、常见错误与解决方案

### 5.1 400 请求的租户标识未传递

**错误**：`{"code":400,"msg":"请求的租户标识未传递"}`

**原因**：缺少 `tenant-id` 请求头。RuoYi-vue-pro 在多租户模式下要求所有请求带此头。

**解决**：在所有请求中添加 `tenant-id: 1` 头。

---

### 5.2 401 账号未登录（已登录但仍 401）

**错误**：`{"code":401,"msg":"账号未登录"}`

**原因**：
1. Swagger Authorize 按钮未生效（已知 Bug）
2. Token 已过期（默认 12 小时）
3. 请求头格式错误

**解决**：
- 每个接口的参数表单中填写 `tenant-id: 1` 和 `Authorization: Bearer <token>`（不要填 Bearer 前缀，只填 token）
- 或重新登录获取新 token

---

### 5.3 405 Request method 'POST' not supported

**错误**：`405 Method Not Allowed`

**原因**：更新和删除操作使用了 POST 方法，但框架规定必须用 PUT（更新）和 DELETE（删除）。

**解决**：
- 更新：`PUT /admin-api/hospital/xxx/update`
- 删除：`DELETE /admin-api/hospital/xxx/delete?id=1`
- 不要用 POST 调用更新或删除接口

---

### 5.4 500 系统异常（新增记录时）

**错误**：`500 {"code":500,"msg":"系统异常"}`

**可能原因**：

| 原因 | 诊断方法 | 解决方案 |
|------|----------|----------|
| 数据库序列不同步 | 检查错误信息是否有 "duplicate key" | 运行 fix_seqs.sql 同步序列 |
| 缺少必填字段 | 检查 NOT NULL 约束字段 | 添加缺失字段 |
| 外键引用无效 | 检查 doctorId/patientId 等是否存在 | 先创建关联记录 |

---

### 5.5 床位分配/释放 500 错误

**错误**：`500 系统异常`

**可能原因**：
- 床位状态使用了英文值 `"AVAILABLE"`/`"OCCUPIED"` 而不是中文 `"空闲"`/`"已占用"`
- BedServiceImpl 代码中硬编码了中文判断逻辑

**解决**：确保床位状态使用中文值：
```sql
UPDATE hospital_bed SET status = '空闲' WHERE status = 'AVAILABLE';
UPDATE hospital_bed SET status = '已占用' WHERE status = 'OCCUPIED';
```

---

### 5.6 账单支付返回 BILL_ALREADY_PAID

**错误**：支付已付账单时返回 `BILL_ALREADY_PAID`

**原因**：账单状态为 `"PAID"` 时无法再次支付

**解决**：选择状态为 `"UNPAID"` 的账单进行支付测试

---

### 5.7 就诊新增 500 错误

**错误**：`500 系统异常`

**原因**：`visit_date` 字段在数据库有 `NOT NULL` 约束

**解决**：创建就诊记录时必须包含 `visitDate` 字段：
```json
{ "patientId": 1, "doctorId": 1, "deptId": 1, "visitDate": "2026-04-17T12:00:00", "reason": "..." }
```

---

### 5.8 gsql: command not found

**错误**：docker exec 容器内找不到 gsql

**原因**：gsql 不在容器的 PATH 环境变量中

**解决**：使用完整路径：
```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql ..."
```
