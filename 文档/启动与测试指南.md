# 医院数据管理系统 — 启动与测试指南

> 适用环境：Windows 本地（MySQL 8.0）或 Windows + Docker（OpenGauss）
> 后端端口：48080 | 前端端口：80
> 数据库：MySQL 8.0 (本地, 端口 3306，推荐) 或 OpenGauss (Docker, 端口 5432)
> 默认登录：用户名 `admin`，密码 `admin123`

## 一、环境准备清单

### 1.1 基础软件检查

```bash
# 检查 JDK
java -version
# ✅ 期望：java version "21.x"（LTS，兼容 1.8+)

# 检查 Maven
mvn -version
# ✅ 期望：Apache Maven 3.x.x

# 检查 Node.js（前端启动需要，版本 >= 16.0.0）
node -v
# ✅ 期望：v16.x.x 或更高
```

### 1.2 MySQL + Redis（推荐，零 Docker）

`application-local.yaml` 默认配置为本地 MySQL，后端还需要 Redis 做缓存和 Session 管理。两者都可在 Windows 本地运行，完全不需要 Docker。

**MySQL**：
```bash
# 启动 MySQL 服务（Windows）
net start MySQL80

# 验证连接（默认密码 123456）
mysql -u root -p123456 -e "SELECT 1;"
```

**Redis**：
```bash
# 启动 Redis（Windows 本地安装）
D:\Redis\redis-server.exe

# 验证（另开一个终端）
D:\Redis\redis-cli.exe ping
# ✅ PONG
```

> Redis 默认监听 `127.0.0.1:6379`、无密码，与 `application-local.yaml` 中的配置一致。

MySQL 配置（位于 `ruoyi-vue-pro/yudao-server/src/main/resources/application-local.yaml`）：
```yaml
spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:mysql://127.0.0.1:3306/ruoyi_vue_pro?useSSL=false&serverTimezone=Asia/Shanghai&...
          username: root
          password: 123456
  redis:
    host: 127.0.0.1
    port: 6379
```

> ⚠️ 使用 MySQL 时，数据库初始化请参考 **§4.1 MySQL 初始化**（跳过 OpenGauss 部分）。

### 1.3 Docker 环境（可选 — 仅 OpenGauss 用户需要）

如果选择 OpenGauss 数据库，需要 Docker 来运行它。Redis 已在 §1.2 中用本地方案覆盖，Docker 这边不再重复。

**检查 Docker**：
```bash
docker --version
docker ps
# ✅ 期望：能列出容器列表（可以是空的）
# ❌ 报错 "failed to connect to the docker API" → 先打开 Docker Desktop 等它完全启动
```

确认 OpenGauss 容器正在运行：

| 容器名 | 镜像 | 端口 | 状态 |
|--------|------|------|------|
| opengauss | enmotech/opengauss | 5432 | Running |

**如果容器未运行**：
```bash
docker start opengauss
```

**如果首次部署（容器还不存在）**：

> ⚠️ 国内网络直连 Docker Hub 容易超时，以下命令使用了 DaoCloud 镜像源。

```bash
docker run -d --name opengauss \
  -e GS_PASSWORD=Hospital@2026 \
  -p 5432:5432 \
  --privileged=true \
  docker.m.daocloud.io/enmotech/opengauss:latest
```

验证：
```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d postgres -c 'SELECT 1;'"
# ✅ 返回 1 行结果，说明数据库连接正常
```

> 💡 **如果没有本地 Redis**：可以顺手用 Docker 跑一个 Redis 容器作为补充：
> ```bash
> docker run -d --name redis -p 6379:6379 redis:7-alpine
> ```

## 二、后端启动流程

> ⚠️ **首次启动顺序说明**：必须先完成 §4 数据库初始化，再启动后端！如果数据库未初始化（表不存在），后端虽然能启动，但登录、API 调用都会失败。简言之：**先 §4 → 再 §2 → 最后 §3。**

### 2.1 编译 + 运行（推荐方式）

```bash
cd 项目根目录/ruoyi-vue-pro

# 第一次运行需要先编译安装（跳过测试）
mvn install -DskipTests

# 启动后端（必须指定 local profile，否则找不到数据库配置）
mvn spring-boot:run "-Dspring-boot.run.profiles=local"

> ⚠️ **Windows 中文超长路径测试坑**：当**项目根目录位于含中文的深层路径**下时，执行 `mvn test` / `mvn package`（不带 `-DskipTests`）时，Maven surefire fork 出的 JVM 的 classpath 会乱码，导致 `ClassNotFoundException`。
> 
> **解决办法**：打包/编译时务必加 `-DskipTests`（或 `-Dmaven.test.skip=true`）。
> 
> **单元测试**：项目含 33 个 Mockito 单元测试（位于 `ruoyi-vue-pro/yudao-module-hospital/src/test`，覆盖全部 10 个业务模块：并发占床/支付幂等、就诊终态守卫、删药引用守卫、床位容量，以及科室/医生/患者/病房的级联删除与数据隔离、统计接口非管理员拒绝），已在短路径验证全绿，无需在长路径下重复运行。
> 
> **本地跑测试**：把项目复制到短路径（如 `D:/proj`）再 `mvn test`，或直接在 IDE 中 Run 测试类。
```

> 💡 **Maven 镜像加速**：国内网络直接下载依赖很慢。可以在 `~/.m2/settings.xml` 中配置阿里云镜像：
> ```xml
> <mirror>
>   <id>aliyun</id>
>   <mirrorOf>central</mirrorOf>
>   <name>Aliyun Maven Mirror</name>
>   <url>https://maven.aliyun.com/repository/public</url>
> </mirror>
> ```

**查看启动日志**：启动失败时，除了 Maven 控制台输出，日志文件位于：

```
C:\Users\<用户名>\logs\yudao-server.log
```

（即 `${user.home}/logs/yudao-server.log`，在 Windows 上展开为 `C:\Users\<你的用户名>\logs\yudao-server.log`）

### 2.2 验证后端启动成功

访问 Swagger 文档：

```
http://localhost:48080/doc.html
```

或健康检查：

```bash
curl http://localhost:48080
```

看到 JSON 响应说明启动成功。

**验证 Redis 连通性**：后端依赖 Redis 做缓存和 Session 管理。后端启动后，检查控制台是否出现 Redis 连接失败的报错：

```
❌ Unable to connect to Redis; nested exception is ...
```

如果出现此错误，确认 Redis 容器已运行（`docker ps | grep redis`），且 `application-local.yaml` 中 Redis 配置为 `host: 127.0.0.1, port: 6379`（无需密码）。

## 三、前端启动流程（可选）

项目配备了 Vue3 管理后台界面（yudao-ui-admin-vue3），启动后可直观操作。

> **前置条件**：Node.js >= 16.0.0（`package.json` 中 `engines.node` 要求）。检查版本：
> ```bash
> node -v
> ```

**前端如何调用后端 API？**

`.env.local` 中配置了 `VITE_BASE_URL='http://localhost:48080'` 和 `VITE_API_URL=/admin-api`，前端直接向 `http://localhost:48080/admin-api/...` 发请求。Vite 的 proxy 被注释掉了（因为后端已开启 CORS），所以不需要额外配置代理。

```bash
cd 项目根目录/yudao-ui-admin-vue3

# 💡 国内用户建议先切换 npm 镜像源（否则 npm install 会很慢）

# 启动前端开发服务器
npm run dev
```

启动后浏览器访问 `http://localhost`（端口 80），即可看到登录页面。系统已配置单租户模式，直接输入用户名密码登录即可。

## 四、数据库初始化

### 4.1 MySQL 初始化（推荐）

使用本地 MySQL 8.0，`sql/mysql/` 下的脚本一步到位（含框架表、医院业务表、菜单、字典、测试数据）：

```bash
cd 项目根目录/ruoyi-vue-pro

# 创建数据库
mysql -u root -p123456 -e "CREATE DATABASE IF NOT EXISTS ruoyi_vue_pro DEFAULT CHARACTER SET utf8mb4;"

# 导入框架 SQL + 医院业务 SQL
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/mysql/ruoyi-vue-pro.sql
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/mysql/hospital.sql

# 验证
mysql -u root -p123456 ruoyi_vue_pro -e "SELECT COUNT(*) AS users FROM system_users; SELECT COUNT(*) AS depts FROM hospital_department;"
# ✅ 期望：users > 0，depts >= 0
```

#### 4.1.1 医院业务测试数据（开箱即用）

若想直接体验数据统计、床位占用、处方发药、账单支付等功能，无需手动逐条录入，可导入 `ruoyi-vue-pro/sql/hospital-test-data.sql`。该脚本会先清空全部 `hospital_*` 业务表（不影响用户/角色/菜单等框架表），再按系统**正常业务流程**写入一套相互一致的丰富样例数据：

> 科室(6) → 医生(10) → 病房(8)+床位(52) → 药品(12) → 患者(25) → 就诊(85) → 处方(67)+处方明细(132) → 账单(67)

导入命令（默认库名为 `ruoyi_vue_pro`）：

```bash
cd 项目根目录/ruoyi-vue-pro
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/hospital-test-data.sql
```

导入后可立即在后台看到真实数据，并验证三个数据统计接口（见 §7.2）：

| 接口 | 说明 | 期望数据量 |
|------|------|-----------|
| `GET /admin-api/hospital/stats/visit-trend` | 就诊趋势（按天） | 45 条（2026-06-01 ~ 07-15） |
| `GET /admin-api/hospital/stats/ward-usage` | 床位使用率 | 8 条（病房） |
| `GET /admin-api/hospital/stats/medicine-stock` | 药品库存预警 | 12 条 |

> ⚠️ **必须带 `--default-character-set=utf8mb4`**，否则中文科室/药品名称会报 `ERROR 1366 Incorrect string value`。
> ⚠️ **会清空现有业务数据**：脚本开头对 10 张 `hospital_*` 表执行 `DELETE` 再重新 `INSERT`。如需保留已有业务数据请勿执行；它不会影响框架表。
> ⚠️ **多租户**：脚本把全部演示数据的 `tenant_id` 统一置为 `1`（与管理员 `admin` 的租户一致），因此默认只有管理员能看到这些数据。若你的管理员租户不是 `1`，请把文件末尾 `UPDATE hospital_* SET tenant_id = 1;` 里的 `1` 改成你的 `tenant_id`，否则业务/统计页面查不到数据。
> 💡 脚本可**重复执行**（先 `DELETE` 再 `INSERT`，且 id 显式指定），不会因重复导入报错。

#### 4.1.2 权限与账号关联（医生开方 / 患者支付 / 数据隔离）

为打通「医生开方、患者支付、数据仅自己可见」，需执行权限修复脚本。**权限模型、角色矩阵与设计取舍详见《总体设计文档》§2.3**，执行命令如下（**幂等，可重复执行**）：

```bash
cd 项目根目录/ruoyi-vue-pro
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/hospital-permissions-fix.sql
```

> ⚠️ 第 3 步的 `145`/`146` 是本项目库中 `doctor001`/`patient001` 的 `system_users.id`，导入到别的库时请按实际账号 id 调整。若重新导入了 §4.1.1 的测试数据，需再次执行本脚本以恢复账号关联。
> ⚠️ **执行后必须清权限缓存**：脚本直接 `INSERT system_role_menu`，而 yudao 把"角色-菜单"授权缓存在 Redis（`menu_role_ids:` 等键）。若不清除，后端仍按旧缓存判定 → 医生开方 / 患者支付**依旧 403**。执行完二选一：① 重启后端；② 清空 Redis 权限缓存（本机无密码时 `D:\Redis\redis-cli.exe flushdb`）。注意 `flushdb` 会清掉所有 Session，下次访问需重新登录。
> 💡 脚本幂等，可重复执行；重新导入 §4.1.1 测试数据后需重跑以恢复账号关联。

### 5.3 登录获取 Token

**方式 A — curl（WSL / Git Bash）**：

```bash
curl -X POST http://localhost:48080/admin-api/system/auth/login \
  -H "Content-Type: application/json" \
  -H "tenant-id: 1" \
  -d '{"username":"admin","password":"admin123"}'
```

**方式 B — PowerShell（Windows 原生，推荐）**：

```powershell
Invoke-RestMethod -Uri "http://localhost:48080/admin-api/system/auth/login" -Method Post -ContentType "application/json" -Headers @{"tenant-id"="1"} -Body '{"username":"admin","password":"admin123"}' | ConvertTo-Json
```

响应中的 `data.accessToken` 字段即为 token。

## 六、常见错误与解决方案

### 6.1 400 请求的租户标识未传递

**错误**：`{"code":400,"msg":"请求的租户标识未传递"}`

**原因**：缺少 `tenant-id` 请求头。RuoYi-vue-pro 在多租户模式下要求所有请求带此头。

**解决**：在所有请求中添加 `tenant-id: 1` 头。

---

### 6.2 401 账号未登录（已登录但仍 401）

**错误**：`{"code":401,"msg":"账号未登录"}`

**原因**：
1. Swagger Authorize 按钮未生效（已知 Bug）
2. Token 已过期（默认 12 小时）
3. 请求头格式错误

**解决**：
- 每个接口的参数表单中填写 `tenant-id: 1` 和 `Authorization: Bearer <token>`
- 或重新登录获取新 token

---

### 6.3 405 Request method 'POST' not supported

**错误**：`405 Method Not Allowed`

**原因**：更新和删除操作使用了 POST 方法，但框架规定必须用 PUT（更新）和 DELETE（删除）。

**解决**：
- 更新：`PUT /admin-api/hospital/xxx/update`
- 删除：`DELETE /admin-api/hospital/xxx/delete?id=1`
- 不要用 POST 调用更新或删除接口

---

### 6.4 500 系统异常（新增记录时）

**错误**：`500 {"code":500,"msg":"系统异常"}`

**可能原因**：

| 原因 | 诊断方法 | 解决方案 |
|------|----------|----------|
| 数据库序列不同步（OpenGauss） | 检查错误信息是否有 "duplicate key" | 运行 fix_seqs.sql 同步序列 |
| 缺少必填字段 | 检查 NOT NULL 约束字段 | 添加缺失字段 |
| 外键引用无效 | 检查 doctorId/patientId 等是否存在 | 先创建关联记录 |

---

### 6.5 床位分配/释放 500 错误

**错误**：`500 系统异常`

**可能原因**：
- 床位状态值不匹配（代码使用枚举 `BedStatusEnum.FREE(0)=空闲 / OCCUPIED(1)=占用`，数据库需一致）
- OpenGauss 序列未同步

**解决**：确保床位状态使用整数值：
```sql
-- MySQL
UPDATE hospital_bed SET status = 0 WHERE status IN ('FREE', '空闲', 'AVAILABLE');
UPDATE hospital_bed SET status = 1 WHERE status IN ('OCCUPIED', '已占用');
```

---

### 6.6 账单支付返回 BILL_ALREADY_PAID

**错误**：支付已付账单时返回 `BILL_ALREADY_PAID`

**原因**：账单状态为 1（已支付）时无法再次支付

**解决**：选择状态为 0（未支付）的账单进行支付测试

---

### 6.7 就诊新增 500 错误

**错误**：`500 系统异常`

**原因**：`visit_date` 字段在数据库有 `NOT NULL` 约束

**解决**：创建就诊记录时必须包含 `visitDate` 字段：
```json
{ "patientId": 1, "doctorId": 1, "deptId": 1, "visitDate": "2026-04-17T12:00:00", "reason": "..." }
```

---

### 6.8 gsql: command not found

**错误**：docker exec 容器内找不到 gsql

**原因**：gsql 不在容器的 PATH 环境变量中

**解决**：使用完整路径：
```bash
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql ..."
```

---

### 6.9 后端启动报 ClassNotFoundException: org.postgresql.Driver

**错误**：启动时抛出 `java.lang.ClassNotFoundException: org.postgresql.Driver`

**原因**：PostgreSQL 驱动在框架中被标记为 `optional=true`，不会自动传递给 `yudao-server` 模块。

**解决**：在 `yudao-server/pom.xml` 中显式添加依赖：
```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
</dependency>
```
然后重新 `mvn install -DskipTests` 再启动。

---

### 6.10 执行 gsql 报 libxml2.so.2 错误

**错误**：`gsql: error while loading shared libraries: libxml2.so.2: cannot open shared object file`

**原因**：OpenGauss 镜像的 `LD_LIBRARY_PATH` 未包含依赖库路径。

**解决**：确保命令中始终包含 `export LD_LIBRARY_PATH=/usr/local/opengauss/lib;`，不要直接用 `gsql` 简写。
```bash
# ❌ 错误写法
docker exec opengauss gsql ...

# ✅ 正确写法
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql ..."
```

---

### 6.11 端口 48080 已被占用

**错误**：后端启动时报 `Address already in use: bind` 或 `Port 48080 was already in use`

**解决**：
```bash
# Windows — 找到占用 48080 的进程并杀掉
netstat -ano | findstr :48080
taskkill /PID <进程ID> /F
```

---

### 6.12 端口 80 绑定失败（Windows）

**错误**：前端 `npm run dev` 时报 `EACCES: permission denied 0.0.0.0:80`

**原因**：Windows 非管理员用户绑定 80 端口需要特殊权限。

**解决**：
- **方案 A**：以管理员身份运行终端再执行 `npm run dev`
- **方案 B**：修改 `.env` 中 `VITE_PORT=8080`，换一个不需要特权的端口

---

### 6.13 npm install 速度极慢 / 超时

**原因**：默认 npm registry 在境外，国内访问慢。

**解决**：切换淘宝镜像源后重试：
```bash
npm config set registry https://registry.npmmirror.com
npm install
```

## 八、环境重置与清理

开发过程中需要"推倒重来"时，按以下步骤操作：

### 8.1 MySQL 重置

```bash
# 删库重建
mysql -u root -p123456 -e "DROP DATABASE IF EXISTS ruoyi_vue_pro; CREATE DATABASE ruoyi_vue_pro DEFAULT CHARACTER SET utf8mb4;"

# 重新导入 SQL（同 §4.1）
cd 项目根目录/ruoyi-vue-pro
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/mysql/ruoyi-vue-pro.sql
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/mysql/hospital.sql

# （可选）重置后想立刻看到演示数据，可再导入测试数据
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/hospital-test-data.sql

# 重置会清空业务表、丢失测试账号与业务档案的关联，需重跑权限与账号关联脚本
mysql -u root -p123456 --default-character-set=utf8mb4 ruoyi_vue_pro < sql/hospital-permissions-fix.sql
```

### 8.2 OpenGauss 重置（Docker）

```bash
# 删除旧数据库并重建
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d postgres -c 'DROP DATABASE IF EXISTS ruoyi_vue_pro;'"
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d postgres -c 'CREATE DATABASE ruoyi_vue_pro;'"

# 重新导入 SQL（按 §4.2.2 ~ §4.2.4 的顺序）
cd 项目根目录/ruoyi-vue-pro
docker cp sql/opengauss/ruoyi-vue-pro.sql opengauss:/tmp/
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -f /tmp/ruoyi-vue-pro.sql"
docker cp sql/opengauss/hospital.sql opengauss:/tmp/
docker exec opengauss bash -c "export LD_LIBRARY_PATH=/usr/local/opengauss/lib; /usr/local/opengauss/bin/gsql -U gaussdb -W Hospital@2026 -d ruoyi_vue_pro -f /tmp/hospital.sql"
# 如有菜单 SQL 同样重新导入
```

### 8.3 彻底清理容器

```bash
docker stop opengauss redis
docker rm opengauss redis
# 数据卷不会被自动删除，重新 docker run 后会继续使用旧数据
# 如需彻底清空数据卷：docker volume prune（慎用，会删所有未使用的卷）
```

## 十一、前端 .env 配置说明

前端启动时 `npm run dev` 实际执行 `vite --mode env.local`，加载 `.env.local`。重要开关：

| 变量 | `.env` 默认值 | `.env.local` 覆盖值 | 说明 |
|------|-------------|-------------------|------|
| `VITE_PORT` | `80` | — | 前端端口（Windows 非管理员可能需要改为 `8080`） |
| `VITE_BASE_URL` | — | `http://localhost:48080` | 后端地址 |
| `VITE_APP_CAPTCHA_ENABLE` | `false` | `false` | 登录验证码（已关闭） |
| `VITE_APP_TENANT_ENABLE` | `true` | `true` | 多租户（需要 `tenant-id` 头） |
| `VITE_APP_API_ENCRYPT_ENABLE` | `true` | —（继承 `.env`） | API 请求体 AES 加密 |
| `VITE_APP_TITLE` | `医院挂号管理系统` | `体检评价与健康档案系统` | 页面标题 |

> ⚠️ `VITE_APP_API_ENCRYPT_ENABLE=true` 时前端会加密请求体。如果 curl 测试遇到问题，在 `.env.local` 中加 `VITE_APP_API_ENCRYPT_ENABLE=false` 可临时关闭。
